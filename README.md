# xlsx2grand

Конвертер выгрузок **xlsx** (ведомость объёмов работ и локальный сметный расчёт из ГРАНД-Сметы) в **XML ГРАНД-Сметы** (внутренний формат обмена `<Document Generator="GrandSmeta">`, кодировка `windows-1251`).

Утилита независимая: один статический бинарь на Go, без внешних зависимостей (xlsx читается через `archive/zip` + `encoding/xml`).

## Как работает

```
ВОР.xlsx ──┐
           ├─► сопоставление по «№ в ЛСР» ─► XML ГРАНД-Сметы
Смета.xlsx ┘
```

1. Из **сметы** берётся шапка (ЛСР, объект, стройка, основание, регион, уровень цен), разделы, позиции с шифрами, ресурсы (труд рабочих, машины, материалы), цены и коэффициенты.
2. Из **ВОР** берутся наименование работ, единица, количество и формула расчёта; порядок строк и подзаголовки разделов формируют структуру `Chapters → Header → Position`.
3. Сопоставление строк ВОР с позициями сметы — по колонке «№ в ЛСР».

В выходном XML: запятая как десятичный разделитель, символы вне windows-1251 (например `∅`) — числовыми ссылками `&#x2205;`, порядок ресурсов по схеме `Tzr → Tzm → Mch → Mat`, общие коэффициенты вынесены одним блоком документа.

## Сборка

```bash
go build -o xlsx2grand ./cmd/xlsx2grand
```

Требуется Go 1.22+.

## Использование

```bash
xlsx2grand -vor "ВОР.xlsx" -smeta "Смета.xlsx" -out "result.xml"
```

| Флаг | По умолчанию | Назначение |
|---|---|---|
| `-vor` | — | xlsx ведомости объёмов работ (обязателен) |
| `-smeta` | — | xlsx локального сметного расчёта (обязателен) |
| `-out` | рядом с ВОР | путь к выходному XML |
| `-version` | `15.3.3.54868` | `ProgramVersion` в корне документа |
| `-composer` | `—` | подпись составителя |

Отчёт о сопоставлении печатается в stdout: число разделов и строк, несопоставленные строки, позиции сметы без строки в ВОР, суммы количества.

## Docker

```bash
docker build -t xlsx2grand .
docker run --rm -v "$PWD:/data" xlsx2grand \
  -vor "/data/ВОР.xlsx" -smeta "/data/Смета.xlsx" -out "/data/result.xml"
```

Образ — multi-stage на `alpine`, итоговый слой содержит только бинарь.

## Структура проекта

```
cmd/xlsx2grand/       CLI: флаги, отчёт о сопоставлении
internal/xlsx/        минимальный читатель .xlsx (sharedStrings, A1-адресация)
internal/vor/         парсер ведомости объёмов работ
internal/smeta/       парсер ЛСР: шапка, разделы, позиции, ресурсы, коэффициенты
internal/grand/       генератор XML ГРАНД-Сметы и windows-1251
```

## Структура входных xlsx

### Ведомость объёмов работ

Один лист. Заголовок таблицы в строках 4–5 (`№ п/п`, `№ в ЛСР`, `Наименование работ`, `Ед. изм.`, `Кол-во`, `Формула расчёта`), данные — ниже.

| Колонка | Содержимое |
|---|---|
| A | `№ п/п`; `Раздел N. Название`; подзаголовки без номера |
| B | `№ в ЛСР` — ключ сопоставления со сметой |
| C | наименование работ |
| D | единица измерения (`100 м3`, `1000 м2`, `шт` …) |
| E | количество (число) |
| F, G | ссылки на чертежи |
| H | формула расчёта объёма |
| J | коэффициент применения |

Строка считается позицией, если в B стоит число, а в C — текст. Строка с текстом только в A и пустыми B/C — подзаголовок раздела.

### Локальный сметный расчёт

Один лист, печатная форма «Приложение № 3».

| Область | Содержимое |
|---|---|
| строки 1–34 | шапка: № ЛСР, наименование стройки/объекта, вид работ, основание, уровень цен, субъект РФ, редакция нормативов |
| строки 35–38 | многоуровневая шапка таблицы |
| с 39 | разделы (`Раздел N. …`), позиции, ресурсы, итоги |

Колонки основной таблицы:

| Колонка | Содержимое | В XML |
|---|---|---|
| A | № п/п; `Н` — материал не учитывается | `Position Number` |
| B | шифр: `ГЭСН…`, `ФСБЦ…`, `ТЦ_…`, `49-1`; у коэффициентов — приказ/приложение | `Code` |
| C | наименование; `ОТ(ЗТ)`, `ЭМ`, `М`, `НР …`, `СП …`, `Итого…`, `Всего по позиции` — служебные строки | `Caption`, итоги не переносятся |
| H | единица измерения (`шт`, `т`, `чел.-ч`, `маш.-ч`) | `Units` |
| I | количество на единицу | `Quantity` ресурса |
| J | коэффициент | коэффициент ресурса |
| L / M / N | базовая цена / индекс / текущая цена | `PriceBase` / индекс / `PriceCurr` |
| P | всего в текущих ценах | для сверки |

Ресурсы распознаются по шифру: `1-100-xx` — труд рабочих (`Tzr`), `4-100-xx` — труд машинистов (`Tzm`/`Tzm2022`), `91.xx.xx-xxx` — машины (`Mch`), прочее — материалы (`Mat`). Строка коэффициента — текст со значениями вида `ОЗП=1,2; ЭМ=1,2; ТЗ=1,2`.

> В репозитории нет самих файлов выгрузок — только описание их структуры.

## Ограничения

1. **Формула количества.** Печатная форма ВОР не содержит формул с идентификаторами (`Ф9`, `А1`) — переносится итоговое число. В XML количество записывается числом, а не выражением.
2. **Заголовки подразделов** привязываются к позициям по порядку следования в ВОР.
3. **Вид работ (`Vr2001`)** в выгрузке не печатается и не переносится.
4. Материалы, помеченные в смете как не учитываемые, в выгрузку не попадают.
5. Цена материала выгружается только при наличии; отсутствующие цены остаются пустыми.

## Проверка результата

Выходной файл — `windows-1251`, CRLF, валиден по схеме ГРАНД-Сметы (`OpenXML_LS`):

```bash
xmllint --noout --schema OpenXML_LS_2026.2.3.xsd result.xml
```

## CI

GitHub Actions (`.github/workflows/build.yml`) собирает бинарь под `linux/amd64` и `linux/arm64`, прогоняет `go vet` и загружает артефакты сборки.
